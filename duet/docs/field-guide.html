Duet Field Guide

Claude plans and orchestrates. GPT‑6 Astra audits the plan, the delegation and the diff — from the identical sealed context. A phase runs from approval to commit without asking you anything.

workers: sonnet + gpt‑5.6‑sol · auditor: gpt‑6‑astra @ high · all on subscription billing

The one idea. Both models read the same sealed bundle — the brief, the repo state, the plan, and the delegation table — hashed so a verdict can always be traced to the exact input it was formed against. Astra isn't reviewing a diff. It's reviewing the decision.

Everything else in the plugin exists to make that review binding rather than advisory: a hook that refuses work, not a prompt that discourages it.

How a phase runs

You approve a plan. That is the only place duet asks you anything until the commit has landed.

How you invoke it

One command does the whole arc. The others exist for when you want a single piece of it. 

/duet:wrap [path/to/plan.md]     ← the one you'll use

Use it after brainstorming and writing-plans have produced a plan and you've approved it. duet does not re-plan; re-planning would throw away the better plan and produce a worse one. /duet:run "<what you want>" is the same arc when no planning skill was involved.

CommandWhat it's for
/duet:wrapRun an approved plan end to end. The main entry point.
/duet:runSame, but plans first. For when no planning skill was used.
/duet:briefCatch up across every project — what moved, what Astra flagged, what needs you.
/duet:auditFire one checkpoint by hand: plan, batch, feature, premerge.
/duet:bundleSeal a context bundle, or render the one both models read.
/duet:dispatchRoute and run tickets across both families.
/duet:commitReview the diff, then commit and push. Refused without clearance.
/duet:gateInspect a block, or clear it with a recorded reason.
/duet:phaseShow or move the cycle by hand.
/duet:statusMode, Codex readiness, current bundle, remaining quota.
/duet:setupFirst-run check: Codex installed, logged in, billing to the subscription.
/duet:modeSwitch which checkpoints fire automatically.

The audit loop, and its three exits

This is the part that changed most recently, and the part worth understanding, because it is where the tokens used to go.

exit 1
It converges. Usually round 1 or 2. The gate opens, the phase advances, and on a code checkpoint the exact diff is cleared for commit.
exit 2
It stops converging. Identical findings twice running means the fix isn't landing, so a third round would buy the same paragraph again. The loop ends there — this is what usually ends it.
exit 3
It runs out of rounds. 5 for the plan, 7 for the final review. Work proceeds with the findings on the record. Set audit.onCap to halt if you'd rather it stopped.
Cost to keep in mind. A phase that fights through both checkpoints can want 5 + 7 = 12 auditor calls, against a rolling budget of 24 per 5 hours with 2 held in reserve. Two contentious phases will exhaust the window — duet quota show is where to look when an audit starts getting skipped mid-run.

What enforces what

Six hook events. None of them are advice; each one either allows a thing or refuses it, in a separate process that Claude does not control.

EventDoesRefuses when
PreToolUseInspects every tool call that could change somethingThe cycle hasn't reached audited, or a blocking verdict stands
StopDecides whether the turn may endA cycle is mid-phase and has a defined next step
PostToolUseStarts a cycle when an approved plan is written—
SessionStartSurfaces gate readiness, registers the project for the dashboard—
SubagentStartLogs the dispatch to .duet/activity.jsonl—
SubagentStopCloses the log entry, trims the log—

Why the Stop hook can't trap you

It holds the turn open so a phase doesn't end halfway. Four things make sure it lets go:

  • A ceiling. Three refusals at the same point and it hands the turn back.
  • Surrender sticks. Once it has given up at a point it stays given up until something changes.
  • Progress resets the budget. The count is per state, not per session, so a long phase is never punished for being long.
  • It stands aside on escalation. A closed gate with no rounds left means duet decided it wants you — holding the turn there would trap you in the one case it built to reach you.

Turn it off entirely with duet config set audit.autoContinue false.

Where the state lives

Two places, and the split matters: anything per-project sits in the repo where you can read it, and only the cross-project ledger is global.

PathHolds
<repo>/.duet/phase.jsonThe cycle and its history
<repo>/.duet/bundles/Every sealed bundle, with lineage
<repo>/.duet/gate.jsonThe standing block, if any
<repo>/.duet/gate-history.jsonEvery block and how it ended
<repo>/.duet/audit-rounds.jsonRounds spent, verdict fingerprints, escalations
<repo>/.duet/stop-gate.jsonContinuation counter for the Stop hook
<repo>/.duet/activity.jsonlWhich subagents ran, and when
~/.claude/duet/config.jsonSettings
~/.claude/duet/quota.jsonThe rolling 5-hour ledger
~/.claude/duet/projects.jsonRegistered projects for the dashboard

.duet/ is gitignored, so cycle state does not travel with a clone. A project blocked on one machine arrives on another with an open gate — one machine per cycle.

Settings worth knowing

duet config set audit.maxRounds 5          # plan-audit cap
duet config set audit.maxRoundsByCheckpoint.premerge 7
duet config set audit.onCap proceed        # or: halt
duet config set audit.stopOnRepeat true    # stop on identical findings
duet config set audit.autoContinue true    # Stop hook holds the turn
duet config set audit.maxContinues 3
duet config mode plan-premerge             # which checkpoints fire

The agents

AgentModelGatedFor
duet-prior-artopusnoDeep research on a domain — how it works, what’s been built, where attempts stall. Called whenever planning needs more than it has.
duet-researchersonnetnoWeb research during planning
duet-scoutsonnetnoReading the codebase without filling your context

duet-workersonnetyesDoing the work on Anthropic tickets

The four read-only agents are exempt from the gate on purpose: research during planning is exactly the work that should happen before a plan is sealed, and a gate that blocked it would push planning toward guesswork.

If something looks wrong

  • duet doctor --probe — makes two real calls and tells you whether Codex is billing your ChatGPT subscription or an API key. Run it before trusting any setup; it's what caught an invented CLI flag that silently broke every audit.
  • duet status — mode, current bundle, remaining quota.
  • duet gate show — what's blocking and why.
  • duet dash — every registered project at once.
  • duet bundle show — the exact text both models read.
